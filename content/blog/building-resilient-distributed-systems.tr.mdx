## Dağıtık Sistemlerde Hata Kaçınılmazdır

Network partition, node failure, latency spike — bunlar normaldir. Önemli olan sistemin bu hataları zarifçe yönetmesidir.

## Resilience Pattern'ları

### 1. Circuit Breaker

Hata oranı eşiği aştığında devre kesici açılır ve istekler hızlıca reddedilir:

```typescript
class CircuitBreaker {
    private state: "closed" | "open" | "half-open" = "closed";
    private failureCount = 0;
    private lastFailureTime: number = 0;

    constructor(
        private readonly threshold: number,
        private readonly resetTimeout: number,
    ) {}

    async call<T>(fn: () => Promise<T>): Promise<T> {
        if (this.state === "open") {
            if (Date.now() - this.lastFailureTime > this.resetTimeout) {
                this.state = "half-open";
            } else {
                throw new Error("Circuit breaker is open");
            }
        }

        try {
            const result = await fn();
            this.failureCount = 0;
            this.state = "closed";
            return result;
        } catch (err) {
            this.failureCount++;
            this.lastFailureTime = Date.now();
            if (this.failureCount >= this.threshold) {
                this.state = "open";
            }
            throw err;
        }
    }
}
```

### 2. Retry with Exponential Backoff

```typescript
async function retryWithBackoff<T>(
    fn: () => Promise<T>,
    maxRetries = 3,
    baseDelay = 100,
): Promise<T> {
    for (let i = 0; i <= maxRetries; i++) {
        try {
            return await fn();
        } catch (err) {
            if (i === maxRetries) throw err;
            const delay = baseDelay * Math.pow(2, i) + Math.random() * 100;
            await sleep(delay);
        }
    }
    throw new Error("Unreachable");
}
```

### 4. Timeout

Her dış çağrı için timeout zorunludur:

```typescript
async function withTimeout<T>(
    fn: () => Promise<T>,
    ms: number,
): Promise<T> {
    const timeout = new Promise((_, reject) =>
        setTimeout(() => reject(new Error(`Timeout after ${ms}ms`)), ms)
    );
    return Promise.race([fn(), timeout]) as Promise<T>;
}
```

### 5. Health Check API

Her servis bir health check endpoint'i sunar:

```go
func HealthHandler(w http.ResponseWriter, r *http.Request) {
    status := map[string]string{
        "database":  checkDB(),
        "kafka":     checkKafka(),
        "redis":     checkRedis(),
        "blockchain": checkBlockchainNode(),
    }

    healthy := true
    for _, s := range status {
        if s != "ok" {
            healthy = false
        }
    }

    if !healthy {
        w.WriteHeader(http.StatusServiceUnavailable)
    }
    json.NewEncoder(w).Encode(map[string]interface{}{
        "status": status,
        "healthy": healthy,
    })
}
```

## Gerçek Dünya Senaryosu

Blokzincir altyapısında yaşadığım bir senaryo:

1. **Node düştü** → Circuit breaker açıldı, yeni işlemler kuyruğa alındı
2. **Retry mekanizması** → Backup node'a geçiş yapıldı
3. **Bulkhead** → Exchange işlemleri etkilenmeden devam etti
4. **Monitoring** → 10 saniye içinde uyarı alındı, otomatik failover tetiklendi

Sonuç: Sıfır kullanıcı etkisi, 30 saniyede tam recovery.

## Özet

| Pattern | Ne Zaman | Ne İşe Yarar |
|---------|----------|--------------|
| Circuit Breaker | Hızlı hata tespiti | Cascade failure'ı önler |
| Retry | Geçici hatalar | Kendiliğinden düzelir |
| Bulkhead | Kaynak izolasyonu | Bir bileşenin tüm sistemi çökertmesini engeller |
| Timeout | Bekleme süresi kontrolü | Sonsuz bekleme (hang) engeller |
| Health Check | Sistem durumu | Load balancer ve monitoring için |

Unutma: Dağıtık sistemde her şey hatalıdır, ta ki doğru olduğu kanıtlanana kadar.
