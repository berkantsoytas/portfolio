## Başlangıç: Polling

Her şey basit bir polling loop ile başladı:

```typescript
setInterval(async () => {
    const blocks = await blockchainNode.getLatestBlocks();
    for (const block of blocks) {
        await processBlock(block);
    }
}, 3000); // Her 3 saniyede bir
```

Sorunlar:
- 3 saniye gecikme — çok yavaş
- Boş yere API çağrısı — kaynak israfı
- Blok kaçırma riski — poll interval'ı yetmezse
- Backpressure yok — işlem yığılması

## Dönüşüm: Event-Driven

```go
func main() {
    // Block stream consumer
    stream := blockchain.SubscribeBlocks()

    for block := range stream {
        go func(b Block) {
            metrics.RecordBlockDelay(time.Since(b.Timestamp))

            if err := pipeline.Process(b); err != nil {
                log.Error("block processing failed", "block", b.Number, "err", err)
                dlq.Send(b, err)
                return
            }

            metrics.RecordBlockProcessed(b.Number)
        }(block)
    }
}
```

Çözülenler:
- Gerçek zamanlı — blok gelir gelmez işlenir
- Push-based — boş yere polling yok
- Worker pool — backpressure kontrolü
- Dead letter queue — hata yönetimi

## Performans Karşılaştırması

| Metrik | Polling | Event-Driven |
|--------|---------|--------------|
| Latency | 3s (avg) | 200ms (avg) |
| CPU usage | %35 idle polling | %5 idle |
| Max throughput | 100 tx/s | 10,000+ tx/s |
| Error handling | Manual | Automatic (DLQ) |

## Öğrenilenler

Event-driven'a geçiş sadece teknolojik bir değişim değil, aynı zamanda zihinsel bir dönüşümdür. "Şimdi ne yoklayacağım?" yerine "Hangi event'i dinleyeceğim?" sorusunu sormaya başlıyorsunuz.
